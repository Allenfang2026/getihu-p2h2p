# 结构图版式目录 · 7 种

> 每种版式挂三个标签：**数据形状**（选型的主键）、**场合**、**读者时间**。
> **选型只看数据形状，不看题材。**「这页讲战略」不是选金字塔的理由，「这页的数据是 3–6 层递进、每层一个概念」才是。选型规则以 `~/.claude/skills/p2h2p/SKILL.md` 的 **Step 3.8** 为准。
> 「姊妹」列 = 同一批内容可能两种版式都排得下的对子，用于换版式，不代表两版都要生成。

## 共用口径（七种版式全适用）

**数据入口统一**。调用方传的是**已解析好的 JavaScript 对象**，不是 YAML 字符串——本目录里的 YAML 示例只是给人看的书写形态，实际调用前要先转成对象（`slides/p{NN}.json` 里本来就是 JSON）。七种版式的调用签名完全一致：

```js
const res = await DIAGRAM_LAYOUTS[版式名].render(svgEl, data, { scope: cardEl });
// res = { nodes, bounds, viewBox, projection, ...版式各自的附加字段 }
```

`render` 是 **async**（内部要 `await` 字体就绪后才能测量文字宽度），必须 `await`；漏了 `await` 拿到的是 Promise，图也可能在字体加载完成前就量偏了。

**颜色字体全部跟随当前 deck**。版式内部一律走 `DIAGRAM.fromDeck(opts.scope)` 从 `scope` 元素上取 CSS 变量（`--color-primary` / `--color-bg` / `--color-ink` 等，兼容 `--primary` / `--bg` / `--ink` 等别名），再生成 9 级明度阶。**任何版式文件里都没有写死的颜色**，换个 deck 模板、或者把图放进不同 `scope` 的容器，图自己就变。深色底 deck 自动反向取字色（AA 对比度兜底）。字体走 `font-family: inherit`，跟着 deck 的字体栈走。

**投屏硬闸**。每个 `render` 收尾都会自己调一次 `DIAGRAM.enforceProjection(svg)`，把低于下限的线宽、字号顶上去，结果放在返回值的 `projection` 字段里（`{fixed, strokes, fonts, details}`）。builder 要读这个数——修正量大说明版式选错了，见 Step 3.8。

**畸形数据一律跳过不报错**。七种版式的 normalize 都只认对象和字符串，`null` / `undefined` / 数字 / 布尔、以及空文字项全部丢弃，不会生成看不出内容的空白盒子。所以数组里有空洞不会崩，但也**不会有任何提示**——数据条数对不上时先怀疑这里。

## D1 · 金字塔 pyramid

**文件**：`layouts/pyramid.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.pyramid`

**数据形状**：层级递进的扁平层数组，第 0 项是塔尖。层与层之间**没有父子关系**——第 2 层不隶属于第 1 层，只是垫在它下面。常见 3–6 层。

**数据格式**：

```yaml
title: 投后评价指标体系          # 可选，render 不画标题，由卡片外壳画
layers:                          # 从顶到底
  - text: 总体评价结论
    note: 成功 / 基本成功 / 部分成功    # 可选，层内小字
  - text: 准则层
    note: 四个维度加权汇总
    items:                       # 可选，层内挂的要点，扁平一串，不再往下递归
      - 过程规范性
      - 目标达成度
      - 效益可持续性
  - text: 指标层
    note: 共 18 项可量化指标
    items: [概算执行率, 结算审减率, 产能利用率]
  - text: 基础数据层
```

层也可以直接写字符串（`- 愿景`），等价于 `{text: 愿景}`。`items` 的元素同样可以是字符串或 `{text}`。字段别名：`text` 可写 `label`，`items` 可写 `points`。

**适用场合**：评价指标体系（目标层—准则层—指标层）、战略—战术—执行、能力金字塔、马斯洛式的递进结构。

**姊妹关系**：层与层只有内外之分、没有高低之分 → 换 **D2 同心圆**；层其实是并列的几类 → 换 **D5 分组**；层之间是先后顺序 → 换 **D4 流程**。

**已知限制**：

- 层数越多塔尖越窄。代码注释明写「8 层时顶层文字放不下是必然的」，兜底是把塔尖文字挪到梯形右侧引出。所以**超过 6 层就该考虑拆页或换版式**，别硬塞。
- **8 层以上时靠下几层的色阶会相同**（明度阶只有 9 级，摊不开），递进感这时全靠梯形宽度承担，颜色帮不上忙。

## D2 · 同心圆 concentric

**文件**：`layouts/concentric.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.concentric`

**数据形状**：从内到外的包含关系，扁平数组，第 0 项是圆心（实心圆），其余是圆环。层与层**无高低之分，只有内外**。常见 3–5 环。

**数据格式**：

```yaml
title: 评估机构能力圈层
rings:                           # 从内到外，第 0 项是圆心
  - text: 注册资产评估师团队
    note: 核心执业资格            # 可选
  - text: 评估方法与作业规范
  - text: 行业数据库与案例积累
    note: 近五年 1200 余单
  - text: 客户与监管信任关系
```

`rings` 可写 `circles` 或 `layers`；也可以直接把数组作为 `data` 传进去。环项可写字符串。

**适用场合**：核心圈—扩展圈—生态圈、个人—团队—组织—行业、核心技术—产品—市场。

**姊妹关系**：外层是"垒在"内层之上而非"包住"内层 → 换 **D1 金字塔**；圈层之间有先后 → 换 **D4 流程**。

**已知限制**：

- 文字**一律水平排在环带的 12 点方向**，不沿弧排列。这是代码注释里写死的有意取舍（沿弧排中文会逐字歪、截图转 PPT 时 textPath 可能整块丢字、行数一多排不下），别指望改回沿弧。
- 每环的文字量要克制。环宽不够时先缩字号（缩到投屏下限为止）再换行，字太多会把整张图撑得很大。
- **圆心文字很长时仍会换行**——圆形容器的固有限制，已做 3 行封顶 + 自动缩字号兜底，但圆心本来就该放最短的那个词。

## D3 · 鱼骨图 fishbone

**文件**：`layouts/fishbone.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.fishbone`

**数据形状**：**单一结果 + 多类原因**。一条水平主干指向右端的结果，主干上交替向上下伸出斜刺（大类原因），每根斜刺上再挂水平小刺（具体原因）。常见 4–6 根大刺、每根 2–5 条小刺。

**数据格式**：

```yaml
spine: 概算执行率偏离超过 15%      # 结果 / 问题，画在最右端
bones:                            # 大类原因
  - text: 设计变更
    causes: [地质条件与勘察不符, 功能需求中途追加, 规范升级]
  - text: 材料价格
    causes: [钢材市场波动, 运距超出预估]
  - text: 工期管理
    causes: [征拆滞后, 雨季停工超预期, 交叉作业干扰]
  - text: 合同与计量
    causes: [清单漏项, 计量口径分歧]
```

`bones` 可写 `categories` 或 `causes`；每根刺的 `causes` 可写 `children` 或 `items`。小刺元素可写字符串或 `{text}`。

**适用场合**：质量归因、事故复盘、偏差分析、人机料法环式的问题拆解。

**姊妹关系**：只有一层原因、没有大类分组 → 换 **D5 分组** 更清爽（代码注释里的原话）；原因之间是先后而非并列 → 换 **D4 流程**。

**已知限制**：

- 上下分配走贪心按子项数平衡（不是奇偶轮流），所以刺的上下位置**由数据决定、不由书写顺序决定**——想让某根刺一定在上面，做不到。
- **小刺是裸文字，没有底色框**（只有大刺有）。所以小刺文字压在连线附近，密度高时可读性下降快，每根刺的小刺控制在 5 条以内。
- 刺数超过 6 根时整张图会变得很宽，配合投屏硬闸检查。

## D4 · 流程图 flow

**文件**：`layouts/flow.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.flow`

**数据形状**：**有先后顺序的步骤**序列，一个维度（时间/顺序）。可编号。

**数据格式**：

```yaml
title: 投后评价作业流程
numbered: true                    # 可选，步骤盒左上角标序号
steps:
  - text: 立项与资料清单
    note: 明确评价范围与口径       # 可选，步骤内小字
  - text: 现场踏勘与访谈
  - text: 数据核对与指标测算
    branch: 数据缺口回补，超三次则出具受限说明   # 可选，该步下方挂虚线分支框
  - text: 成功度打分
    note: 四维度加权
  - text: 出具报告并送审
    branch: 评审意见逐条回应后定稿
```

步骤可直接写字符串（`- 需求受理`）。`branch` 可写字符串或 `{text}`。

**适用场合**：作业流程、项目阶段、审批链路、方法论的执行顺序。

**姊妹关系**：步骤之间没有先后、只是并列的几件事 → 换 **D5 分组**；步骤是层层递进垒上去的 → 换 **D1 金字塔**。

**已知限制**：

- 超过 5 步自动折成**蛇形**多行——**偶数行的阅读方向是从右往左**。这是有意取舍：打字机式折行需要一条横穿整图的回扫线，太吵；蛇形省掉回扫线，方向靠箭头标明。读者跟箭头走不会错，但如果这页要打印成不带箭头的黑白稿，先确认还读得懂。
- 步骤盒统一等宽等高（取所有步骤的最大需求值），所以**有一个特别长的步骤会把所有盒子都撑宽**。
- 步数太多（9 步以上）时单页会很挤，考虑拆页。

## D5 · 逻辑分组图 grouped

**文件**：`layouts/grouped.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.grouped`

**数据形状**：**并列的若干组，每组带若干要点**，组与组之间无层级。这是咨询报告正文页的标准版式，也是**最容易滥用的**——只有真的分得出类才用，硬凑的分组比不分组更糟（代码注释原话）。

**数据格式**：

```yaml
title: 评估服务内容
flow: true                        # 可选，组间加箭头表示先后；省略则纯并列
groups:
  - title: 前期准备
    note: 进场前完成               # 可选，组标题下的小字
    items:
      - text: 尽职调查
        note: 产权、合规、财务三线并行   # 可选，卡片内小字
      - text: 评估方案设计
      - text: 作业组人员配置
  - title: 现场作业
    items: [资产盘点与核实, 权属文件收集, 市场询价与比对]
  - title: 成果交付
    items: [评估报告编制, 内部三级复核, 送审答疑与归档]
```

组标题 `title` 可写 `text` 或 `label`；`items` 可写 `points` 或 `children`；要点可写字符串或 `{text, note}`。

**适用场合**：服务内容、能力模块、方案要素、三大板块。

**姊妹关系**：组之间有明确先后 → 加 `flow: true`，或直接换 **D4 流程**；组其实是层层递进 → 换 **D1 金字塔**；所有组挂在一个中心主题下、要强调发散 → 换 **D6 放射**。

**已知限制**：

- 所有组**等宽等高**（取全体最大需求值），**内容量悬殊时短组底部会留大片白**——这是有意取舍（"留白比参差好"），不是布局没算准。想避免就把各组要点数控制得接近些。
- 组数超过 4 自动折成网格，每行从左开始（**打字机式，不走蛇形**——并列关系没有方向，蛇形会让人误以为第二行要从右往左读）。
- **`flow: true` 的组间箭头只在同一行内画，跨行不画**。所以组数多到折行时，行与行之间的先后关系图上没有标记，需要在正文里交代。

## D6 · 放射思维导图 radial

**文件**：`layouts/radial.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.radial` ｜ **需要 `vendor/d3-hierarchy.min.js`**

**数据形状**：**嵌套树**（有 `children`）。根节点在画布中心，分支向四周辐射。适合"一个主题发散出若干并列方向"。

**数据格式**：

```yaml
title: 资产评估投后评价体系
root:
  text: 资产评估投后评价体系
  children:
    - text: 股权类
      children:
        - text: 被投企业经营状况与财务指标复核
          children: [营收, 毛利率与净利率的同业对标偏离度]
        - text: 估值
          children: [市盈率法]
    - text: 工程建设项目类评价
      note: 含市政、建筑、环保改造三类       # 可选，节点下小字
      children: [投资, 进度偏差, 概算执行率与结算审减率双口径核对]
    - text: 成功度打分
      emphasis: true                        # 可选，该节点字重加一档
      children: [权重, 评委会现场质询记录归档]
```

`root` 可省略（直接把根节点对象作为 `data` 传）。`children` 可写 `nodes` 或 `items`。节点可写字符串。层数不限，但 `opts.maxDepth` 可截断。

**适用场合**：品牌关键词、能力地图、议题拆解，需要"发散张力"的门面页。

**姊妹关系**：分支多、层深、需要规整对齐 → 换 **D7 左右树**（同一份数据直接换版式，颜色不变）；有明确先后或上下级落差 → 代码注释明写"不适合放射"，走 **D4 流程** 或 **D7**。

**已知限制**：

- 角度排布靠**迭代扩半径**收敛，最多迭代 5 次，之后即使还挤也放弃。
- 文件头注释里写明这是**「紧凑度换零穿透」的取舍**：宁可整张图散开一些，也不让连线穿过节点。所以分支特别多时外圈会散得很开，整张图偏圆偏大，**塞进 16:9 一页不如 D7 紧凑**。
- d3.tree 的等尺寸假设靠两处修正绕开（半径步长按该层实测最大节点宽定、角度按弧宽二次修正），细节见 `radial.js` 顶部注释。

## D7 · 左右分栏树 bilateral

**文件**：`layouts/bilateral.js` ｜ **挂载**：`window.DIAGRAM_LAYOUTS.bilateral` ｜ **需要 `vendor/non-layered-tidy-tree-layout.js`**

**数据形状**：**嵌套树**，与 D6 完全同一份数据格式。根居中，子节点分左右两侧展开。是"一个主题两三层展开、要塞进 16:9 一页"最稳的版式。

**数据格式**：与 D6 逐字相同（`{title?, root: {text, children: [...]}}`，支持 `note` / `emphasis`）。同一份数据可以在 D6 和 D7 之间直接换，配色不变（两者共用同一套层级配色实现）。

**适用场合**：体系结构、组织架构、内容目录、分支较多需要视觉平衡的层级树。

**姊妹关系**：分支少（一级分支 ≤4）、想要发散张力和门面感 → 换 **D6 放射**；树其实只有两层、且每个分支下就是几条要点 → 换 **D5 分组** 更整齐。

**已知限制**：

- 左右分组按**叶子数贪心平衡**（不是按分支个数对半），所以**哪个分支落在左边由数据决定，不能指定**。返回值里有 `balance` 字段可以查两侧叶子数差。
- 同父兄弟与不同父的相邻子树**共用同一个间隙参数**（上游库 non-layered-tidy-tree-layout 的限制，见 `vendor/PROVENANCE.md`）。适配层取 `siblingGap` 和 `subtreeGap` 里较大的那个喂进去，整体略松，但绝不会让两棵子树贴在一起。

## 接口与依赖（接入时要知道的）

- **七种版式都导出 `describe()`**，返回 `{name, zhName, dataShape, whenToUse}`，可用来程序化枚举全部版式元信息：

  ```js
  Object.values(DIAGRAM_LAYOUTS).map(l => l.describe());
  ```

  `radial` / `bilateral` 这两个的 `describe()` 是接入阶段补的（它们写在版式自述这个约定定下来之前），只加了这一个导出，渲染逻辑未动。

- **`radial.js` 必须在其他版式之前加载**：D2/D3/D4/D5/D7 的层级配色都调 `DIAGRAM_LAYOUTS.radial.nodeStyleAA`（AA 对比度死区兜底）。这是**软依赖**——radial 没加载时会静默退回 `T.nodeStyle(depth)`，图仍然画得出来，但**颜色会与加载了 radial 时不一致**。要保证"同一份数据换版式颜色不变"，radial.js 就得一起引。
